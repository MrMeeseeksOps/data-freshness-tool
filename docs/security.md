# Security

The evaluator needs SELECT on specific production tables, metadata read permissions, and audit SELECT/INSERT/UPDATE for idempotent MERGE. It needs neither source writes nor object ownership. Separate source-read, configuration-read, and audit-write roles compose the runtime role; administrators own metadata updates and schema migrations. Record grants and review them quarterly. Use a small dedicated warehouse with resource controls and auto-suspend.

Use a dedicated Windows gMSA for scheduled evaluation. Services use LocalService and separate persistent directories. Administrators and SYSTEM own application installation and release pointers; the gMSA gets application/config read and log/textfile modify, not release write. `config/secrets` breaks inheritance and grants only administrators, SYSTEM, and the gMSA. Verify ACLs on actual files after secure delivery. Deployment agents are privileged: isolate their pool and protect pipeline edits and environment approvals.

Use Snowflake key-pair authentication. Deliver keys through a secret-management process, never repository files or task arguments. If encrypted, inject `FRESHNESS_PRIVATE_KEY_PASSPHRASE` from an approved store or use the restricted host environment file according to your policy. The application does not implement a vault client. Protect backups with encryption/off-host ACLs; backups omit the designated secrets directory and private-key extensions. Grafana's database can contain notification tokens, so treat its entire backup as secret material.

Rotate keys using Snowflake's second public-key slot: register the new public key, securely distribute the new private key, run test-connection and a dry run under the gMSA, switch the protected configuration, run an audited check, then remove the old public key. Retain a secure rollback window according to policy. Do not log keys/passphrases. Application logs contain event/status/exception type, not raw connector exception text; connector logs are suppressed. Query IDs remain only in the protected Snowflake audit table, not metric labels.

Prometheus/exporter bind to loopback. Grafana defaults to loopback with anonymous access and user signup disabled. Change default admin credentials locally before allowing an internal interface. Restrict the firewall to domain profile and approved subnets; use TLS and authentication for remote access. Internal plain HTTP is not confidential. Use vendor network requirements for Snowflake HTTPS and certificate checks; never disable certificate validation to fix connectivity. Protect SQL query history and audit retention as operational data.

Security validation requires real ACL inspection, a failed source-write test under the service role in a safe test schema, gMSA task execution, firewall tests from allowed/denied hosts, credential rotation, and confirmation that logs/artifacts contain no secrets. No secrets or actual account credentials are included here.
